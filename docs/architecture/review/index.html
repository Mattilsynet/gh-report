DDD Pattern Review — cherry-pit substrate

A pattern-by-pattern audit of how well the cherry-pit crate family (cherry-pit-core, -app, -gateway, -merger, -projection, -storage, -wq) realises DDD's tactical and strategic patterns. Every verdict is decided by source evidence (type/trait names + file:line), cross-read against the binding ADRs (CHE-0004 EDA+DDD+hexagonal, CHE-0005 single-aggregate). Compiled 2026-07-23.
Three passes ran in sequence and are folded into one matrix below: a surface pass (does the named abstraction exist, is it type-enforced), an adversarial depth pass on the surface-Well patterns (full file:line evidence in bd bead ghr-227343fa, extended by a D2 coverage pass in bd bead ghr-c35a9e0d) checking the Depth column, and a doc-comment-vs-ADR Language consistency pass on the depth-Solid/Governed/Mixed patterns. Four minor language drifts (L1–L4) and five depth gaps (G1–G5) were found; all have since been fixed, governed-ratified, or remain tracked open — see the pattern verdict matrix's Status column.
Framing: cherry-pit is a subtractive substrate — illegal compositions must fail to type-check (AGENTS.md, the gh-report stance). Several DDD patterns are therefore deliberately absent, not missing; the matrix distinguishes "lacking by omission" from "lacking by ratified deferral" wherever an ADR records the choice.

Verdict legend

Well represented first-class trait/type in the substrate, DDD name used verbatim. Partial the responsibility exists but is folded into another construct, or realised without a dedicated named abstraction. Lacking no source trace; either a genuine gap or a ratified deferral (noted per row). By design absent absence is an ADR-ratified design choice, not a gap. Unknown / not checked this dimension was not examined for this pattern in the passes run so far.

Still-open / watch items

  • G5 — single-writer own-store-token seal: STILL OPEN, not sealed. Merger::spawn takes Arc<S>; nothing consumes or seals the caller's clone, so a composition root can retain a second Arc and call store.append() directly, bypassing the queue. Documented and tested-against-regression, but structurally still bypassable today — tracked under epic ghr-9240c862 (mission:ddd-adherence).
  • G1/Command — governed specialization, watch-item ghr-a5bd537b. CHE-0085:R8 (1e79a4d) ratifies MergerArm::handle bypassing HandleCommand as deliberate — a doc-plane classification, not a code fix: arm.rs:78 remains structurally unbounded. Watch-item tracks re-audit of the first production MergerArm impl against this ratification.
  • ACL / Context Mapping — Partial, unchanged. The hexagonal port/adapter seam (cherry-pit-gateway, ReadPort) is the ACL; there is still no named context-map document, and only one production consumer (gh-report) exists today.

L4 lesson: name reuse across a delete-and-reintroduce boundary

L4's root cause: git history shows two different crate families shared the name "pardosa" across a deletion boundary — legacy pardosa-encoding (a binary serialization substrate) was physically deleted (36f0d74), then ~2.5 weeks later the current .pgno/NATS pardosa substrate was imported (050e08d), reusing the name for an unrelated codebase. Doc comments written against the first tenant of the name silently became lies about the second — the store.rs:18 phantom-adapter roster (fixed 9ef607f) is that disease. Lesson: never let a removal comment name a bare identifier a future crate might re-occupy; scope it to the exact artefact removed. (The C4 docs' "pardosa dep explicitly REMOVED" wording at c4/level2-containers.html / level1-context.html is technically correct — no cherry-pit-core dependency — but is left as-is, noted as a contributing amplifier when skimmed out of scope.)

Headline findings

  • Surface abstractions are first-class and type-enforced across all eight "well represented" patterns. Under the depth pass, five hold end-to-end (Solid), two are ratified Governed specializations (Aggregate, Command — CHE-0085:R8, doc-plane, code unchanged), and one remains Mixed (Single-writer — still open, see above).
  • Entity, Factory, and Domain Service are "folded, not missing" — responsibilities present, no dedicated trait, ratified by CHE-0020:R5 (8636c0b). Saga and Process Manager are deliberate non-goals pre-1.0 (CHE-0040). Specification is likewise now a ratified absence, not an unrecorded gap.
  • Net assessment. cherry-pit is a high-fidelity tactical + event-sourcing DDD substrate with strong strategic single-context discipline; omissions cluster exactly where the gh-report subtractive stance predicts (orchestration/multi-context tooling the niche doesn't need). The one remaining un-sealed structural gap is single-writer's composition-root convention (documented and tested, not type/ownership-sealed).
